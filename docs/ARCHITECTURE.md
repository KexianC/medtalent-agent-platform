# 架构与数据边界

本文描述源码的运行组成。独立部署须使用自己的域名、账号、数据库和供应商配置；安装步骤见 [DEPLOYMENT.md](DEPLOYMENT.md)。示例资料与小程序配置不表示已在部署者环境上线。

## 单节点组成

React前台与管理后台共用同源 Express API。开发模式 Vite 5174代理到API8788，保留原Host用于跨站写入验证；生产模式 Node直接提供构建产物。结构化数据默认使用 SQLite WAL，也可通过 `DATABASE_URL` 切换为 MySQL 8；两种后端共用异步仓储契约、参数化查询与事务。不可变文件 blob 始终位于 `DATA_DIR`，不存入 MySQL。

任务调度器与API同进程运行，每秒检查持久化队列，一个时间点执行一个任务。长文档/扫描不会让HTTP请求等待解析结束；UI轮询显示实际状态。不是分布式队列，不能启动多个API副本竞争共享数据库。

## 发布模型

`agents.draft` 和 `agents.published` 分开保存，公共目录/聊天只读取发布快照。编辑草稿不会改变线上模型参数或提示词。发布在同一事务内更新快照、递增版本、写入 `agent_versions` 和审计；归档即停止公开访问；恢复历史版本只改草稿，发布必须再次确认。

## 知识模型

上传原件 → 文档元数据与任务 → 格式解析 → 中文友好切片 → 可选Embedding → 待审核/已生效 → 检索 → 带文档ID/标题/片段位置的内部引用。管理端批量审核按智能体隔离，并将每个勾选项绑定到当时的文档 revision；提交时重新校验版本、真实片段、来源有效性和单节点容量，避免把勾选后更新的内容直接生效。

原件只保存在私有数据目录，不通过静态路由公开。文档ID与blob文件名由服务端生成。查询同时限定智能体、`approved=true` 和 `status=ready`，防止跨库和未审核内容进入上下文。资料更新使用校验和检查，旧任务不能覆盖新版本；移除是软删除且立即排除检索。

知识片段被编码为带明确“资料不是指令”边界的上下文；角色配置不能覆盖平台医疗安全规则。模型回答质量仍需医生/业务专家验收，提示边界不是对模型完全安全或医学准确的保证。

向量以数值数组保存在当前结构化数据库，单节点进行相似度与词法混合计算，不要求外部向量服务。每智能体的单节点检索上限为25000个已生效片段，超出时明确报错，不静默截断。大规模应迁移到专用向量数据库、独立任务队列与可横向扩展的文档存储；当前 MinIO/S3 仅作为 NAS 来源传输层，导入后的不可变文档仍落在平台 `DATA_DIR`。Embedding服务未配置或失败时真实降级为词法检索，模式和告警可见。受控的 `document.reembed` 任务可复用数据库中已经验证完整的片段，仅原子替换向量而不再次读取或解析原件；它与导入/NAS任务双向全局互斥，向量模型、维度、有限数值和归一化任一不符即拒绝提交。

## NAS模型

`sources`绑定智能体与相对目录/对象前缀；环境变量提供全局连接根、bucket 和凭据。只读适配器支持 WebDAV、本地挂载和 MinIO/S3，产出带版本签名的清单；S3 使用完整分页及 ETag、LastModified、Size 条件读取。增量同步检查sha256后提交文档索引任务。清单不完整或任何读取失败时不执行缺失文件移除。修改/删除映射会使正在运行的旧配置任务终止，不跨智能体改写。历史 source 若含服务端连接字段、非法路径或重叠范围会整体 fail-closed；每份 NAS 文档在写入、索引、审核和检索时都重新验证其精确子路径与 source 归属。

`nas-sync-worker` 是单独部署在 NAS 上的上游同步器：只读挂载授权知识目录，按一级目录/显式 slug 映射写入私有 MinIO 前缀。它以稳定文件检查、SHA-256 metadata、HEAD 回读、原子状态清单和默认不删除策略保护源数据。全局对象前缀不能为空；加载状态后会在创建 S3 客户端或执行任何对象调用前，验证每个文件键、待迁移键和孤儿键严格属于当前命名空间，并验证文件键可由已记录源路径重新派生，畸形或旧状态一律 fail-closed。平台使用另一组只读 S3 身份，Worker 无权发布或审核知识。

## 数据与隐私

- 后台用户密码使用随机salt+scrypt；会话令牌仅以哈希入库，浏览器获得HttpOnly/SameSite=Strict Cookie。
- 管理路由统一校验角色，未知角色拒绝；生产启动拒绝已知开发默认密码。账号修改会撤销其会话。
- 管理写入校验Origin/Fetch-Site；可选服务令牌只从服务端环境读取。供应商可由管理后台配置，已有密钥不通过公开接口返回；服务器负责加密存储和调用。
- 所有公开与管理响应都使用按资源定义的固定字段投影；不透传历史 JSON/SQLite 中的任意额外字段。可识别认证格式、私钥块及当前环境凭据值会在文档、引用、下载文件名、账号、任务和模型输入/输出中遮蔽；遮蔽标记动态选择不与任何当前凭据碰撞的分隔符。AI Studio 对完整结构化成功响应递归清理，聊天与 TTS 成功响应先完整缓冲以覆盖跨帧敏感串/字节，ASR 文本在返回前清理。流式 TTS 只接受内联音频；普通 TTS 只允许内联音频或精确白名单内的 DashScope 北京结果桶 HTTPS 地址，不跟随重定向或任意供应商 URL。公开API不返回systemPrompt、模型密钥、NAS凭据或私有文档原件。
- 服务端 `usage` 记录智能体、模型、检索模式、耗时、成功/错误、时间等请求元数据。游客记录保存在客户端本机；启用微信账户后，用户主动保存或迁移的账户资料、健康记录及业务数据由消费者存储持久化。部署者须为服务器数据目录及数据库设置访问控制、备份与删除流程。
- 用户问答、相关历史和经同意的健康摘要会发送给模型；语音发送给语音服务；导入知识可发送给Embedding服务。运营方需选择合规供应商/自托管端点。

## 恢复与扩展

工作器启动时将中断任务恢复为queued；可重放任务以文档ID/校验和去重。失败保留错误和审计，通过后台重试。SQLite 备份先取一致性快照，在私有快照上执行 WAL checkpoint、切换到 `journal_mode=DELETE` 并通过 `integrity_check`，再复制该快照引用的不可变 blob。MySQL 备份在一致性只读事务中导出业务表，同时锁住平台实例与 blob 维护边界，并记录运行时 schema、表/序列摘要、业务不变量、向量和 blob manifest。两类备份都只在全部校验通过后原子发布完成 manifest；恢复只允许新的空目标，详见 `MYSQL_MIGRATION.md`。

扩展到多实例前，需要逐项验证组织权限与数据隔离、身份接入、患者记录存储、外部对象存储、队列工作器、向量数据库、指标监控和共享速率限制。代码中的可选适配器和功能开关不表示部署者已完成相应服务配置或可以直接横向扩容。
